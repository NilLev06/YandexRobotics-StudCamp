# RL: обучение манипулятора GFS-X

Ветка содержит Unity-симулятор и конфигурации ML-Agents для обучения
гусеничного манипулятора видеть, находить и захватывать объект. Это безопасный
контур для экспериментов с наблюдениями, наградой и политикой до переноса
поведения на физический робот.

## Содержимое

| Путь | Назначение |
| --- | --- |
| `Assets/` | Сцены, префабы, скрипты агента и ассеты робота. |
| `config.yaml` | Основная конфигурация обучения ML-Agents. |
| `config_fixed.yaml` | Конфигурация обучения фиксированного манипулятора. |
| `TRAINING.md` | Зафиксированный рецепт обучения catch-политики и результаты запусков. |
| `results/` | Артефакты отдельных обучающих запусков. |
| `export_robot_bundle/` | Экспортируемый комплект ассетов робота. |

## Требования

- Unity `6000.5.3f1`;
- Python-окружение с `mlagents` версии, совместимой с пакетом
  `com.unity.ml-agents` `4.0.3`;
- зависимости Unity из `Packages/manifest.json`.

## Запуск обучения

Сначала откройте проект в Unity и соберите среду, если требуется headless-запуск.
Пример запуска фиксированного манипулятора приведён в
[`TRAINING.md`](TRAINING.md):

```bash
conda activate mlagents
export GFSX_ARENA_COUNT=40
mlagents-learn config_fixed.yaml --run-id=<run-id> --env=Build/GFSX_Simulator \
  --num-envs=6 --no-graphics
```

Не перезаписывайте результаты успешного запуска: используйте новый `run-id` и
фиксируйте параметры, исходные веса и метрики.

## Принципы работы

- Меняйте одну гипотезу за раз: наблюдения, действие, награду или
  рандомизацию окружения.
- Оценивайте политику отдельно от обучения; рост награды не равен надёжному
  захвату.
- Перенос на физический манипулятор выполняйте только через ветку
  [`unity-real-manipulator`](../../tree/unity-real-manipulator) и контролируемую
  проверку оборудования.
