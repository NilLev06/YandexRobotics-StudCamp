# Внесение изменений

## Выберите правильную ветку

- `rover` — ROS 2, Docker и код реального мобильного робота.
- `rl` — обучение и симуляция манипулятора.
- `unity-real-manipulator` — Unity-интеграция реального манипулятора.
- `main` — навигационная документация и базовые Unity-ассеты.

Перед началом работы обновите нужную ветку и создайте тематическую ветку от неё.
Не объединяйте независимые проекты одной большой правкой.

## Что проверять

- Документация: ссылки, команды и названия веток должны быть актуальны.
- Unity: не коммитьте `Library/`, `Temp/`, `Logs/`, локальные сборки и IDE-кэши.
- ROS/rover: следуйте `AGENTS.md` в ветке `rover`; проверки без движения должны оставаться безопасными по умолчанию.

## Перед pull request

1. Опишите цель, затронутую ветку и способ проверки.
2. Не добавляйте ключи, пароли, телеметрию, фотографии людей или данные доступа.
3. Для изменений, касающихся оборудования, явно укажите, выполнялась ли проверка только в симуляции/dry-run или под наблюдением оператора.
